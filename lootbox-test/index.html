Lootboxes

Емулює батьківську сторінку: змінюйте дані нижче, завантажуйте їх у iframe через query-параметри (імітація першого завантаження) або через postMessage (імітація пізньої відповіді бекенду) і дивіться всі повідомлення від віджета в лозі.

Сценарій і картки

Список нижче — це і є вміст ряду. Поля, які віджет у поточному стані картки не читає, вимкнені; наведіть курсор, щоб побачити чому.

setContent надсилає весь ряд із форми — усі картки зі списку вище, а не лише ту, яку ви щойно правили.

«Згорілий день» позначає поточний активний день як missed, робить наступний активним і надсилає весь ряд через setContent — тобто рівно те, що зробить ваш бекенд наступного дня. Віджет сам знаходить різницю й програє перехід.

setCardState оновлює одну картку — кнопка в її рядку вище. Так виглядає відповідь вашого API на клік.

Мок бекенду (симуляція відповіді API)

Обираєте, що «поверне бекенд» при кліку на активну картку, і затримку відповіді. Пісочниця ловить cardClick і через задану затримку надсилає setCardState — так само, як робитиме ваш реальний бекенд. Віджет крутить «зарядку» кулі, поки чекає, а потім спалахом відкриває результат. Відповідь мока перезаписує і рядок форми — це видно в лозі.

Тільки для тесту

Ці команди не використовуються в продакшен-інтеграції. Вони потрібні лише для ручного тестування віджета в цій пісочниці.

Кнопка playOpen для кожної картки — у відповідному рядку вище. Запускає анімацію відкриття без реального кліку і одразу підганяє рядок форми під результат. На locked і missed вимкнена: там вона створила б стан, якого в проді не буває.

Кроки інтеграції (шпаргалка)

Стислий флоу. Повний контракт — у INTEGRATION.md. Popup, blur і UI поза каруселлю реалізує FE на prod-сторінці.

  1. Вставити iframe з даними карток у query-параметрах або короткий URL + setContent після ready (для великих/динамічних наборів).
  2. Слухати ready; на resize — оновити висоту iframe.
  3. На cardClick (available) — одразу робити запит до API. Віджет крутить «зарядку» кулі, поки ви чекаєте відповідь.
  4. Коли API відповів — надіслати setCardState з результатом (prize/prediction). Віджет спалахом відкриває результат.
  5. На animationComplete (після спалаху) — показати перший popup результату.
  6. Повторний клік по сьогоднішньому prize/prediction — знову popup (без анімації).

⚠️ Коли рендерити popup: cardClick приходить у двох випадках — розрізняйте за data.state. На state:'available' (перший клік) popup НЕ показуйте — лише стартуйте запит до API (результату ще немає). Перший popup — тільки на animationComplete. На повторний cardClick зі state:'prize'/'prediction' — можна показати popup знову. Ніколи не вішайте popup на «будь-який cardClick».
